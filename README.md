# HTTPS 证书信任检测

一个纯静态页面，用浏览器尝试访问公开的 eMudhra 测试端点，观察当前浏览器和网络是否能建立连接。

## 本地预览

在此目录运行：

```sh
python3 -m http.server 8000
```

然后打开 <http://localhost:8000>。

## 结果说明

- HTTP 响应成功仅表示本次连接路径取得了响应，应继续检查浏览器、代理和证书链。
- 请求失败不能单独证明证书已吊销，JavaScript 无法区分证书校验、CT、DNS、CORS 和网络错误。
- 页面不会读取操作系统证书库，不会修改系统设置，也不会保存检测记录。
- 开始检测时，浏览器会向页面列出的第三方测试主机发送不带凭据的请求。对方可能看到出口 IP 和请求元数据。

本工具用于辅助排查，不构成安全证明。请勿绕过浏览器证书警告。

## 确认证书拒绝

普通网页无法读取 TLS 错误码，自动请求失败始终标为原因待确认。跨域请求失败后会尝试 `no-cors`，以减少依赖 CORS 响应头造成的误判；该模式不会暴露 HTTP 状态码，也不能证明失败原因。

失败项可以填入从本行测试地址复制的确切浏览器错误码：

- `ERR_CERT_REVOKED` / `SEC_ERROR_REVOKED_CERTIFICATE`：检测通过，手动确认吊销拒绝。
- `ERR_CERT_AUTHORITY_INVALID` / `SEC_ERROR_UNKNOWN_ISSUER`：检测通过，手动确认信任拒绝；不能据此确认吊销或本次事件封禁。

DNS、超时、证书过期、域名不匹配及 Safari 的笼统安全警告均不标记通过。手动确认依据用户输入，不是网页自动获取的证据；代理也可能改变实际校验的证书链。重新检测会清除所有手动确认。
